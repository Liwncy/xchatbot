# 人格源文件

一人一个 md。改完跑 `npm run data -- run persona:build`，生成 `.docs/sql/persona.sql`，再用 `d1:migrate:*:persona` 灌库（删表重建）。

## 放哪

```
.docs/persona/<分类>/<role_key>.md
```

- 文件夹名就是分类，要先登记到 `scripts/sync/persona-build.cjs` 的 `CATEGORIES`，没登记的文件夹会报错。
- 文件名（去掉 `.md`）就是 `role_key`，全库唯一，用英文小写，代码里按它找人格。
- 只读分类文件夹下直接那一层的 `.md`，这个 README、子文件夹、其他格式都不读。

## 怎么写

```
---
name: 佛系
triggers: 随便,无所谓
ack: 行，佛系。
sort: 50
---

正文：就是给模型的人格提示词。
```

头（两条 `---` 之间）每行一个 `键: 值`，值从第一个冒号后面算起：

| 键 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 人格名，`#人格 名字` 靠它切 |
| `triggers` | 否 | 别名，逗号或分号隔开（`,` `，` `;` `；`） |
| `ack` | 建议写 | 切过去时回的那句，像随口说的话 |
| `sort` | 否 | 整数，默认 100，越小越靠前 |
| `status` | 否 | 默认 `active`，写别的就不参与匹配 |

正文：

- 头后面的全部内容，原样当提示词，只去掉首尾空行。
- 不用转义，引号、括号、emoji 随便写。
- 建议写法：先一句「你现在演……」，再按「说话方式」「正事处理」「禁止事项」「对话示例」四段排，小标题固定四个字、用书面词。
- 例子每组两行：`对方：……` `你：……`，写 2～3 组，至少有一组是问事实的正事，示范「先答案，口气后加」（像佛系这种正事转交别人办的，不用）。
- 不能是空的。

## 排序和编号

- 分类按 `CATEGORIES` 里的顺序排，类内按 `sort`，再按 `role_key`。
- `id` 不用写，生成时从 1 起依次编。
- 用 `#加人格` 加的接在最后一个 `id` 后面，分类记为「自定义」。

## 灌哪些

`ENABLED`（同在 `persona-build.cjs`）里列的分类才会写进 `persona.sql`，没列的 md 留着不灌。

## 出错会怎样

缺头、缺 `name`、正文为空、`sort` 不是整数、`role_key` 重复、文件夹没登记，生成都会直接报错，不会写出半份文件。
